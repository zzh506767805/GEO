# 写内容

替商家写的东西统称“内容”。不同平台的稿子不是同一份文字换个排版，所以每一条内容都有一个**类型**：稿子长什么样、谁来写、商家在哪审、确认后怎么交，都跟着类型走。

| 类型 | `type` | 谁写 | 商家在哪审 | 确认后 |
| --- | --- | --- | --- | --- |
| 公众号文章 | `wechat` | 委派 `wechat-writer` 子 Agent，只出排版预览 | 工作台上点“看排版预览” | 委派它存进公众号草稿箱 |
| 小红书笔记 | `xhs` | 你自己 | 工作台上直接看 | 商家复制去发 |
| 长文（知乎、头条号、百家号、搜狐号） | `text` | 你自己 | 工作台上直接看 | 商家复制去发 |
| 抖音视频文案 | `douyin` | 你自己 | 工作台上直接看 | 商家照着拍，复制标题和话题去发 |

每种类型的稿子怎么写、登记带哪些字段，在 `references/writing.md`。**写稿之前先读它。**

内容登记、改状态用的是工作台的脚本，每条命令写全路径：

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" contents
```

下文的 `add-content`、`mark-content`、`contents`、`publish` 都是这个脚本的子命令。

## 红线

这几条也要原样交代给 `wechat-writer`，它看不到你的角色设定。

1. 只写店铺资料里有的事实和店铺数据里查得到的内容，数字必须有出处。你另外记下、商家还没确认的信息（别的叫法、已经关掉的旧店）不写进稿子。
2. 图片地址、小程序路径、链接只能来自查询结果或商家提供的内容。
3. 遵守商家提过的写作要求（店铺资料里的 `writingRules`）：口吻、不用的词、每篇必须带的信息。
4. 只为商家自己的官方账号准备内容，不代注册、不代管账号、不向第三方媒体投稿。
5. 存入草稿箱和发布之前，必须得到商家对这一篇的明确确认，并提醒按平台要求标注 AI 生成。

## 能不能写

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-profile/scripts/geo_state.py" status
```

- `canWrite` 为 false：资料不是从店铺后台读的，商家也还没确认。这时不写，请他看一眼工作台的“监测设置”；脚本也不会让你登记。
- `pendingConfirm` 为 true：`toConfirm` 里那几样还没经过商家确认，不写进稿子。

## 定类型

看三样东西：这一期每个 AI 最常读哪里（算分输出或 `show` 的 `sourcesByProvider`）、这家店在哪里没有内容（周报里找的内容缺口）、商家有哪些账号（店铺资料的 `channels`）。**按数据定类型，不按你能写什么定。**

| 情况 | 写什么 |
| --- | --- |
| 某个 AI 读抖音的占比排在前面 | 抖音视频文案 |
| 某个 AI 读公众号的占比排在前面 | 公众号文章 |
| 某个 AI 读知乎、头条、百家号、搜狐号的占比排在前面 | 长文，`whereToPost` 写清建议发在哪 |
| 某个 AI 读小红书的占比排在前面 | 小红书笔记 |
| 读得最多的是地图、点评、工商信息、电话黄页这类资料页 | 不写内容，在周报的建议里请商家去补门店资料，写清是数据里的哪个网站 |
| 商家说过自己没有那个平台的账号 | 换成他有账号的平台；都没有就写长文 |
| 商家点名要某一种 | 按他说的写，`origin` 写 `asked` |

`reason` 里写依据，数字照抄脚本输出，例如“豆包 45% 的引用来自抖音”。

店铺资料里没记他的账号（`channels` 是空的），不等于他没有：照数据定类型，告诉商家时说一句“这篇适合发在你的抖音号上，没有这个号就跟我说，我换一种写”。他说了自己的公众号、抖音号，按 `geo-profile` 记下来。

同一个主题发两个平台，按两种类型各写一条、各自登记，不要把一种类型的稿子搬到另一个平台。

## 选题

1. **正面回答一道没提到本店的问题**（默认）。从这一期没提到本店的问题里挑一道：这家店有真实内容可写；AI 回答这道题时引用的内容里，你打算写的那种类型占比不低；最近四期没有为同一道题写过。`forQuestion` 填这道题的编号。
2. **写一篇带日期的信息说明**（少数情况）。这一期报告里有会让顾客跑错地方或买错东西的说法，出处又是别人写的、改不了原文时，换成它。同一件事只写一次。`forQuestion` 留空。
3. 两者都没有合适的：这一期不写，用 `set-actions` 把原因写进 `contentNote`。

每期主动写 1 篇，最多 2 篇，不写内容相近的批量稿（脚本会卡住第 3 篇）。

## 写完怎么交

不管是每周主动写的，还是商家临时要的，都按这四步：

1. **登记**：

   ```bash
   python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" add-content --file "$YOUZAN_AGENT_SESSION_TEMP/geo/content.json"
   ```

   ```json
   {"type": "text", "title": "", "bodyFile": "", "reason": "", "forQuestion": "q07", "whereToPost": "知乎", "origin": "weekly"}
   ```

   登记了，工作台“内容”页才有它，商家才能按“第 4 篇”跟你对。只在对话里给的稿子，回头谁都找不到。
2. **同步**：`publish`。每周出周报时，等小结写完一起同步就行。
3. **告诉商家**：类型、标题、两三句摘要，和工作台“内容”页的链接。不在对话里贴全文；商家明确要看时再贴，贴登记的那一版。
4. **等他确认**，再按这种类型的“确认后”去做。

## 商家针对某一篇来说话

序号是工作台上显示的“第 N 篇”。拿不准时先 `contents` 对一下。

| 商家说 | 做法 |
| --- | --- |
| “写一篇公众号文章：……”“写一条小红书笔记：……”“同一个主题再写一条小红书笔记” | 按那种类型重新写一份（不拿别的稿子删减），`origin` 写 `asked` → `add-content` → `publish` |
| “第 4 篇可以发” | `mark-content --no 4 --status confirmed` → 按这种类型的“确认后”去做：公众号文章委派 `wechat-writer` 存草稿箱，再 `mark-content --no 4 --channel 公众号草稿箱 --ref <草稿编号>`；其他类型请他在工作台上复制去发 → `publish` |
| “把第 4 篇存进公众号草稿箱” | 只有公众号文章能存，而且要已确认。同上一行 |
| “第 4 篇我已经发了” | `mark-content --no 4 --status published --channel <发在哪>` → `publish` |
| “第 4 篇标题改短一点”“第 4 篇再改一下：……” | `contents --no 4` 取回稿子 → 改稿（公众号文章让 `wechat-writer` 改，拿新的预览链接）→ `add-content` 带上 `"no": 4`，只传改了的部分 → `publish`。确认过的稿子改了会变回“等你确认”，请他再看一眼 |
| “第 4 篇不发了” | `mark-content --no 4 --status dropped` → `publish` |
| “这周先不写” | 用 `set-actions` 把原因写进 `contentNote` → `publish` |
