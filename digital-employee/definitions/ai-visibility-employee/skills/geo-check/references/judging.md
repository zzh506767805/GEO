# 核对规则

读 `brand-digest` 的输出，写两样东西：

- `descriptions`：AI 点名介绍这家店时怎么说。每一期都写。
- `issues`：这些说法里，和店铺资料对不上的具体事实。有才写，没有就传空数组。

两样都显示在这一期报告的“怎么介绍你”一节里。

## 通用要求

- 只根据输出里的回答原文判断，不凭印象补充。
- `memoryTrace` 为 true 的回答带着之前对话的痕迹，不用来核对。
- `truncated` 为 true 的回答被截短了。需要看全文时，用更大的 `--max-chars` 重新执行 `brand-digest`。

## descriptions：AI 怎么介绍这家店

每个平台写一句话，60 个字左右（最多 120 字），用商家看得懂的话概括这个平台对这家店的定位和主要说法。

- 只写回答里有的内容。
- 不同平台说法矛盾时照实写，不要调和。例如一个说“主打低糖”，另一个说“不是低糖路线”，两句都如实写。
- 某个平台没有可用的回答就不写这个平台。

## issues：和店铺资料对不上的说法

先把分寸想清楚：这是顺带的发现，不是任务。**宁可少记，不要凑数。** 一条记下来，商家就会看到一张“AI 说 / 你的店铺资料里 / 出处 / 怎么改”的卡片，所以每一条都要经得起他追问。

### 什么算

和店铺资料对不上的**具体事实**：

| `fact` | 内容 |
| --- | --- |
| `address` | 门店地址，包括店铺资料里没有的地址、已经搬走或关掉的门店 |
| `hours` | 营业时间 |
| `phone` | 电话 |
| `status` | 门店或店铺是否还在经营 |
| `product` | 招牌商品、规格、产地 |
| `price` | 价格、人均 |
| `other` | 其他具体事实，例如购买入口 |

### 什么不算

- 评价和口味判断，例如“偏甜”“不适合送礼”。这些写进 `descriptions`。
- 说得笼统但没有错，例如只说“在上城区”。
- 没提到本店。这归“有没有提到你”，不是说错。

### 店铺资料里没有的事

资料里没写的事，不能判 AI 说错。但如果各平台说法不一致，或者这是顾客一定会问的信息（营业时间、电话），可以记一条：

- `aiSays`：各平台分别怎么说。
- `truth`：写“店铺资料里没有这一项，现在判断不了哪个对”。
- `fix`：请商家把这项信息告诉你；是店铺后台里该有的，请他补到后台。
- `sourceType` 填 `unknown`，`sourceUrl` 留空。

### AI 自己加了提醒的

AI 说了一个店铺资料里没有的地址，同时提醒“去之前先确认”，仍然可以记，但 `aiSays` 里如实写出它的提醒。

### 每条怎么写

- `id`：英文短编号，格式是“事实类型-短描述”，例如 `address-old-store`。**同一件事每一期用同一个编号**：先看 `knownIssues`，已经有的就沿用。
- `aiSays`：AI 的说法，尽量用它的原话，写明是哪个平台说的。
- `truth`：店铺资料里是怎么写的。看 `facts` 里的 `from`：
  - `backend`（从店铺后台读的）：直接写资料里的内容，例如“只有西溪路一家店，地址是……”。
  - `public`（从公开信息整理的，商家还没确认）：写“我整理的资料里是……”，不要写成“实际是……”。这时对不上不一定是 AI 错。
- `evidence`：出自哪几个回答，用输出里的 `answer` 编号，例如 `b01_hunyuan#1`。
- 出处（`sourceType`、`sourceTitle`、`sourceUrl`）：见下一节。
- `fix`：怎么改，见最后一节。写商家十分钟内能照着做的话；改不动的就照实说改不动。

## 找出处

在这几个回答自己的 `refs` 里，找最可能让 AI 这么说的那一条。

- 从标题和来源判断：旧门店名、旧地址所在的街道、发布时间很早的探店内容、地图或点评上的门店页。
- `sourceUrl` 必须从 `refs` 里**原样复制**，一个字符都不能改。脚本会核对。
- 拿不准是哪一条，就把 `sourceType` 填 `unknown`、`sourceUrl` 留空，在 `fix` 里说明“没有找到明确的出处”。不许猜一条填上。

`sourceType` 的取值：

| 取值 | 是什么 |
| --- | --- |
| `map` | 地图、大众点评、美团、抖音门店这类门店页 |
| `note` | 别人写的笔记、文章、视频 |
| `own` | 商家自己账号发的内容 |
| `other` | 其他页面，例如工商信息、百科 |
| `unknown` | 找不到出处 |

## 怎么改

| 出处 | 改法 |
| --- | --- |
| `map` | 告诉商家去哪个平台，把哪个门店页标记为已关闭或已搬迁；现有门店页上的信息不对的，直接改 |
| `note` | 原文改不了。可以写一篇带日期的门店信息（或商品信息）说明，给 AI 一个新的依据；商家愿意的话，这可以是下一篇内容的选题 |
| `own` | 直接改原文 |
| `other` | 说明这类页面商家自己改不了；工商信息有误的，走变更登记 |
| `unknown` | 照实说没有找到出处，只建议补一篇官方说明 |

不要建议商家去联系别的作者删稿，也不要建议批量发稿把旧内容“压下去”。

## 哪些值得告诉商家去做

记下来的每一条都会出现在报告里。但要不要请商家动手，是另一回事，由你在写本期小结和待办时决定：

- 出处是 `map` 或 `own`：商家自己改得动，一般值得写进待办。
- 出处是 `note`、`other`、`unknown`：商家改不了原文。只有它确实会让顾客跑错地方、买错东西时，才在小结里提一句；否则留在报告里就够了。
- 同一条连续几期都在、商家没有理会：不要每期都催。
