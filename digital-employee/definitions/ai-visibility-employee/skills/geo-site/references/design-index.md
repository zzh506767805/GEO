# 官网的设计参考：先挑一个

官网长什么样，从下面三个设计 Skill 里挑一个，用 `Skill` 工具加载它，按它的做法定方向，再交代给“应用”能力。三个都是 GitHub 上公开的 Skill，原样收在本员工的 `skills/` 下，没有改过。

挑之前先记住：**SKILL.md 第 2 步“官网上放什么”和 `seo-geo.md` 的要求，比设计 Skill 里任何一条都优先。** 设计 Skill 只管长相，不改放什么、不写什么。它要的东西和那两处冲突（比如引外部字体、把常见问题折叠起来、放评价），按那两处来。

## 三个设计 Skill

| Skill | 一句话 | 适合哪种店 |
| --- | --- | --- |
| `qiaomu-design` | 先说清页面的“功能契约”，再定气质；中文排版、信息层级最稳 | **默认用它。** 大多数店：连锁门店、社区店、本地生活、卖货的店 |
| `frontend-design` | 从这家店自己的世界里取一个最有辨识度的东西放在首屏，只大胆一处，其余克制 | 有鲜明个性、商家想“和别家不一样”的店：网红烘焙、设计师品牌、主理人小店 |
| `ui-ux-pro-max` | 用自带的检索脚本按店铺类型查出一整套配色、字体、版式，再按规则清单逐项过 | 没有品牌色、没有明确风格，或商家只要“规规矩矩、像样就行”的店 |

## 怎么挑

按顺序看，第一条对上就用它：

1. 商家自己说了想要的感觉（“要活泼一点”“要高级一点”“像某某家的官网”）：选最接近他说法的那个。
2. 店铺资料里有明确的品牌个性（`edges` 里有让人记得住的特点，店名、招牌商品自带画面感），商家也愿意试：选 `frontend-design`。
3. 没有品牌色、品类很标准、商家只要快和稳：选 `ui-ux-pro-max`。
4. 其余情况：选 `qiaomu-design`。

只加载挑中的那一个。在给商家的方案里用一句人话说清设计方向，不说 Skill 的名字。商家不喜欢，换一个重新出方案。

## 放进做官网的流程里

这三个 Skill 原本是让你自己写页面代码的；做官网时页面由“应用”能力来做，所以只用它们定方向、定规矩，把结果写进给“应用”能力的方案和需求里，测试版出来后再按它们的检查方法看一遍。几处具体的对接：

- **`qiaomu-design`**：走它“从零设计”的路径。它要求出四方向预览页、等人选择；做官网时商家在“应用”能力的方案确认里选，所以在方案里写清推荐方向和备选方向，不另起它的预览回传服务。它要求写的 `DESIGN.md` 写在会话工作区里，作为以后改官网的依据。
- **`frontend-design`**：按它的两步走：先写设计方案（颜色、字体、版式、原则），对照它列的“生成页面的通病”检查一遍，再交给“应用”能力。
- **`ui-ux-pro-max`**：它的检索脚本在本员工的技能目录里，路径是 `"$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/ui-ux-pro-max/scripts/search.py"`（它的 SKILL.md 里写的 `${CLAUDE_PLUGIN_ROOT}` 那个路径在这里不对，用这个）。新官网用 `--design-system`，查询词写店铺类型和品类，不写店名等店铺资料。不要用 `--persist`。

## 效果样例

本仓库根目录的 `官网对比/` 里，有用同一份内容、分别照这三个 Skill 做的有赞龙虾官网，可以看出三种方向的差别。那是给维护的人看的样例，员工给商家做官网时不照抄。
