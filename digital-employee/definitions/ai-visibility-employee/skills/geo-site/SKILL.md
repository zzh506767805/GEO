# 做官网

AI 介绍一家店时，要有地方可读。公众号文章、抖音视频是发在平台上的一篇篇内容；官网是这家店自己的一页资料，一直在线：门店在哪、几点开门、卖什么、怎么买、顾客常问什么，都在一处，说法以店铺资料为准。

官网用有赞的“应用”能力做（`youzan-application` Skill）。本 Skill 管四件事：官网上放什么、长什么样、交给“应用”能力时提哪些要求、做好以后登记到工作台并跟着店铺资料更新。“应用”能力自己的规矩（先把方案说清楚请商家确认、先出测试版、商家说发布才上线）一条都不能省；它的规矩和这里冲突时，以它为准。

本 Skill 自己是个索引，细则在 `references/` 下，用到哪份读哪份：

| 文件 | 管什么 | 什么时候读 |
| --- | --- | --- |
| `references/design-index.md` | 三个设计 Skill（`qiaomu-design`、`frontend-design`、`ui-ux-pro-max`）各适合什么店、怎么挑、怎么放进做官网的流程 | 第 3 步 |
| `references/seo-geo.md` | 让搜索引擎和 AI 读得到、读得懂：页面要求、测试版怎么查、上线以后做什么 | 第 4、5、6 步 |

用到的脚本是工作台的 `geo_report.py`，下文的 `site-brief`、`set-site`、`publish` 都是它的子命令，每条命令都写全路径。

## 什么时候做

- 商家说要做，就做。
- 你主动提，只在下面两种情况，各提一次；商家没接，就不再提：
  1. 这一期报告“怎么介绍你”里，AI 点名介绍这家店时说法对不上，或者说不清门店、营业时间、卖什么。
  2. 商家问“怎么让 AI 更了解我”“怎么让 AI 把我的信息说对”。
- 首次初始化和第一次体检这一轮不提。
- 提的时候说清三件事：官网上放什么；要占用一个应用额度；先出测试版给他看，他说发布才上线。不说“做了官网 AI 就会推荐你”：AI 要先搜得到它才会引用，上线以后看后面几期报告里有没有引用它。

## 1. 先看能不能做

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" site-brief
```

- `canWrite` 为 false：店铺资料不是从店铺后台读的，商家也还没确认。这时不做，请他先看一眼工作台的“监测设置”，确认了再做。
- `site.exists` 为 true、`site.status` 不是 `dropped`：已经有官网了，按下面“改官网、更新官网”做，改的是同一个应用，不要再新建一个。

## 2. 官网上放什么

只用 `site-brief` 输出里的东西，一页从上往下排：

| 块 | 放什么 | 用输出里的 |
| --- | --- | --- |
| 这家店是谁 | 店名、在哪个城市、卖什么；一两句话说清和同类店不一样的地方 | `brand`、`edges` |
| 门店 | 每家门店的名字、地址、营业时间、电话（有才写） | `stores` |
| 招牌商品 | 名字、规格、产地或特点 | `products` |
| 怎么买 | 小程序叫什么、店铺链接 | `buyEntry` |
| 顾客常问 | 一问一答 | `faq` |
| 更新日期 | 页面最下面写“信息更新于 X 年 X 月 X 日” | `today` |

要求：

- **只写 `site-brief` 给出的事实。** 它已经去掉了你另外记下、商家还没确认的信息。哪一块没有资料就不放这一块，不要自己补，也不要凭记忆写。
- **不写价格。** 价格常变，写在官网上很快就过时，AI 引用了就成了说错的信息。想买的人点“怎么买”去店里看。
- 不放顾客评价、排名、奖项、媒体报道，商家给了原文的除外。不用“第一”“最好”“唯一”这类词，不和别家比。
- **顾客常问**：`faq` 里带店名的问题（`kind` 为 `brand`）直接回答。不带店名的问题（`kind` 为 `open`）改成这家店能用事实回答的问法，比如“杭州哪家面包店好吃”改成“西溪附近能买到现烤面包吗”，回答写在哪、有什么、几点开门、怎么买。回答只用上面几块里的事实。
- `oldStores` 不为空、而且 `issues` 里有 AI 说错旧地址的：在门店那一块加一句“原 XX 店已搬到……”或“XX 店已停业”。
- `issues` 是 AI 说错过的事：官网上把对的说法写清楚就行，不要写“网上说的不对”。
- 遵守 `writingRules`：口吻、不用的词、每次必须带的信息。
- 商品图、门店图只用店里真实的图片：商品图用 `youzan-item` 查到的商品主图，链接原样用。生成的图只能当背景、纹理这类装饰，不能画成商品、门店或顾客的样子。没有合适的图就不放。

## 3. 挑一个设计参考

读 `references/design-index.md`，按里面“怎么挑”选一个设计 Skill，用 `Skill` 工具加载它，按它的做法和 `design-index.md` 里写的对接方式定出这个官网的设计方向。下一步写进方案的“整体感觉”。

设计 Skill 只管长相。它和第 2 步、`references/seo-geo.md` 冲突时，以那两处为准。

## 4. 交给“应用”能力做

先用 `Skill` 工具加载 `youzan-application`，按它的步骤走：它会读店铺类型、查应用额度、问清发布渠道和空间类型、给出一版方案请商家确认。**它要问商家的，你一个都不替商家答。**

它的方案里，这几项按下面填，商家改了就按商家的：

| 项 | 填什么 |
| --- | --- |
| 页面用途 | 店铺官网：介绍这家店、门店、招牌商品、怎么买、顾客常问的问题 |
| 用户最想完成的事 | 了解这家店，找到门店或去店里买 |
| 内容是否实时更新 | 内容写死。店铺资料变了，我会提醒你更新官网 |
| 页面结构 | 第 2 步那几块，按表里的顺序 |
| 整体感觉 | 第 3 步定的设计方向。底线是信息好找，像店铺的官方介绍页，不做成促销活动页 |
| 页面标题 | `site-brief` 的 `pageTitle` |
| 页面标识 | `official-site`；被占用了按它的提示换 |
| 空间类型 | 建议选共享空间：在龙虾的其他对话里也能找到、修改这个官网。由商家定 |

它问发布渠道时，可以跟商家说清两种的区别：放在龙虾，是一个单独的网页，电脑和手机都能打开；放进有赞商城，是店铺里的一个手机页面。由他选，不替他选。

另外写进需求里交代给它：

- 一个页面，打开就能看，不用登录；没有表单、下单，不收集顾客的任何信息。
- 文字直接写在页面里，打开页面时不再去取数据：AI 和搜索引擎读页面时不一定会等它取完，取数出错还会白屏。
- 第 2 步的要求原样交代，包括不写价格、只用真实图片。
- `references/seo-geo.md` 里“交给‘应用’能力的页面要求”原样交代：页面头部、正文结构、结构化数据。

## 5. 测试版出来以后

“应用”能力部署好测试版、拿到测试版链接后，先按 `references/seo-geo.md` 的“测试版出来以后查一遍”查页面，有不对的交给它改好、重新出测试版。然后**先登记、同步，再把链接发给商家**（“应用”能力要求发出测试版链接后就停下来等商家）：

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" set-site --status test --test-url "<测试版链接>" --page-name <页面标识>
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" publish
```

链接和页面标识照“应用”能力输出里的原样填。工作台“内容”页最上面会出现官网这一块，带“看测试版”。

然后按“应用”能力规定的格式，把测试版链接原样发给商家，停下来等他回复。

## 6. 商家确认发布以后

按“应用”能力正式发布，再用它给出的正式链接登记、同步：

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" set-site --status published --url "<正式链接>"
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" publish
```

然后告诉商家官网上线了，给正式链接，并建议他在自己能改、能填网址的地方放上这个链接。别处有链接指向它，搜索引擎和 AI 才更容易找到它。

正式发布时，页面的规范链接（`canonical`）和分享卡片里的链接填正式链接，正式版上不能有 `noindex`。`references/seo-geo.md` 的“上线以后”里，商家自己能做的（提交给搜索引擎、robots.txt 不挡爬虫），这一轮挑他用得上的说一两条，不一次全说。

以后 AI 引用了这个官网，报告里会算进“你的内容被引用”，写周报时可以说到。

## 改官网、更新官网

`site-brief` 或 `geo_state.py status` 输出的 `site.outdated` 为 true，说明官网做好以后，店铺资料里官网用到的几样改过了；`site.changed` 写着是哪几样，例如“门店”“招牌商品”。

- 每周出周报时看到，就在建议里提一次：“官网上的门店信息过时了，要更新吗？”商家同意了再更新，没理会就不再提。
- 要更新，或者商家说“官网上……改一下”：重新执行 `site-brief` 拿最新的资料，交给“应用”能力改同一个应用，出测试版，从第 5 步往下走。
- 没有商家这一轮的确认，不正式发布。

## 商家说

| 商家说 | 做法 |
| --- | --- |
| “帮我做个官网” | 从第 1 步开始 |
| “官网可以发布了”“确认发布” | 你这一轮刚把测试版链接发给他：按第 6 步。隔了几轮才说：“应用”能力要求他看到这一轮的测试版链接以后再确认，先重新出一次测试版、发给他，等他再说 |
| “官网上……改一下”“更新官网” | 按“改官网、更新官网” |
| “官网发我” | `site-brief` 输出里的 `site.url`；还没上线，就说还在测试版，给 `site.testUrl` |
| “官网绑好域名了：……” | `set-site --domain <域名>` → `publish`。以后这个域名下的页面被 AI 引用，也算他自己的内容 |
| “官网不要了” | 按“应用”能力下线、删除的流程，商家明确确认后再做；做完 `set-site --status dropped` → `publish` |
