# 做官网

官网是这家店自己的一页资料，一直在线，AI 和顾客都能读到。页面由有赞的“应用”能力（`youzan-application` Skill）来做，页面怎么排、长什么样，按它的流程和商家的意思来；它的规矩（先给方案请商家确认、先出测试版、商家说发布才上线）一条不省，和这里冲突时以它为准。

本 Skill 只管“应用”能力不知道的几件事：

- 官网上写什么：只写店铺资料里的事实，用 `site-brief` 拿。
- 几条内容上的要求：交给“应用”能力时要写进需求。
- 做好以后登记到工作台，店铺资料变了提醒商家更新。

用到的脚本是工作台的 `geo_report.py`，下文的 `site-brief`、`set-site`、`publish` 都是它的子命令，每条命令都写全路径。

## 什么时候做

- 商家说要做，就做。
- 你主动提，只在下面两种情况，各提一次；商家没接，就不再提：
  1. 这一期报告“怎么介绍你”里，AI 点名介绍这家店时说法对不上，或者说不清门店、营业时间、卖什么。
  2. 商家问“怎么让 AI 更了解我”“怎么让 AI 把我的信息说对”。
- 首次初始化和第一次体检这一轮不提。
- 提之前看一眼 `site-brief` 的 `shopCited`（最近一期 AI 引用了几次商城自己的页面）。引用得多，说明 AI 本来就读得到商城里的门店和商品，官网多出来的主要是商城里没有的：这家店和别家哪里不一样、顾客常问的问题、AI 说错过的事的正确说法。照实跟商家说。
- 提的时候说清三件事：官网上放什么；要占用一个应用额度；先出测试版给他看，他说发布才上线。不说“做了官网 AI 就会推荐你”：AI 要先搜得到它才会引用，上线以后看后面几期报告里有没有引用它。

## 1. 先看能不能做

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" site-brief
```

- `canWrite` 为 false：店铺资料不是从店铺后台读的，商家也还没确认。这时不做，请他先看一眼工作台的“监测设置”，确认了再做。
- `site.exists` 为 true、`site.status` 不是 `dropped`：已经有官网了，按下面“改官网、更新官网”做，改的是同一个应用，不要再新建一个。

## 2. 写什么

`site-brief` 输出里已经去掉了你另外记下、商家还没确认的信息，也不带价格。官网上的事实只从这里来；哪一样没有资料就不放，不要自己补，也不要凭记忆写。

官网上要能找到这几样，怎么排、分不分块交给“应用”能力和商家：

| 信息 | 用输出里的 |
| --- | --- |
| 这家店是谁：店名、城市、卖什么，和同类店不一样的地方 | `brand`、`edges` |
| 门店：名字、地址、营业时间、电话（有才写） | `stores`；`oldStores` 见下 |
| 招牌商品：名字、规格、产地或特点 | `products` |
| 怎么买：小程序叫什么、店铺链接 | `buyEntry` |
| 顾客常问：一问一答 | `faq` |
| 页面最下面写“信息更新于 X 年 X 月 X 日” | `today` |

商城里已经有完整的商品和门店页面，官网不用把它们搬一遍：商品挑几样招牌的写清楚，能用 `youzan-item` 查到商品页链接的，链到商城里去看。官网的分量放在商城里没有的东西上：`edges`、`faq`、`issues`。

- **顾客常问**：`faq` 里带店名的问题（`kind` 为 `brand`）直接回答。不带店名的问题（`kind` 为 `open`）改成这家店能用事实回答的问法，比如“杭州哪家面包店好吃”改成“西溪附近能买到现烤面包吗”，回答写在哪、有什么、几点开门、怎么买。回答只用上表里的事实。
- `issues` 是 AI 说错过的事：官网上把对的说法写清楚就行，不要写“网上说的不对”。其中有 AI 说错旧地址的，在门店那里按 `oldStores` 加一句“原 XX 店已搬到……”或“XX 店已停业”。
- 遵守 `writingRules`：口吻、不用的词、每次必须带的信息。
- 页面标题可以用 `pageTitle`，商家想改就按他的。

## 3. 交给“应用”能力做

用 `Skill` 工具加载 `youzan-application`，按它的步骤走。**它要问商家的（发布渠道、空间类型、方案），你一个都不替商家答。** 它的方案里写明：这是店铺官网，内容写死，店铺资料变了你会提醒商家更新。

下面这些写进需求里交代给它，商家要改样子随他，这几条不变：

- 内容就是第 2 步的那些，不写价格。价格常变，写在官网上很快过时，AI 引用了就成了说错的信息。
- 不放顾客评价、排名、奖项、媒体报道，商家给了原文的除外；不用“第一”“最好”“唯一”这类词，不和别家比。
- 商品图、门店图只用店里真实的图片：商品图用 `youzan-item` 查到的商品主图，链接原样用。生成的图只能当背景、纹理这类装饰，不能画成商品、门店或顾客的样子。没有合适的图就不放。
- 文字直接写在页面里，打开页面时不再去取数据：AI 和搜索引擎读页面时不一定会等它取完，取数出错还会白屏。
- 打开就能看，不用登录；没有表单、下单，不收集顾客的任何信息。

## 4. 测试版出来以后

“应用”能力部署好测试版、拿到测试版链接后，**先登记、同步，再把链接发给商家**（“应用”能力要求发出测试版链接后就停下来等商家）：

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" set-site --status test --test-url "<测试版链接>" --page-name <页面标识>
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" publish
```

链接和页面标识照“应用”能力输出里的原样填。工作台“内容”页最上面会出现官网这一块，带“看测试版”。然后按“应用”能力的格式把测试版链接发给商家，停下来等他回复。

## 5. 商家确认发布以后

按“应用”能力正式发布，再用它给出的正式链接登记、同步：

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" set-site --status published --url "<正式链接>"
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" publish
```

告诉商家官网上线了，给正式链接，并照 `set-site` 输出的 `next` 建议他把链接放到自己能填网址的地方：别处有链接指向它，搜索引擎和 AI 才更容易找到它。以后 AI 引用了这个官网，报告里会算进“你的内容被引用”。

## 改官网、更新官网

`site-brief` 或 `geo_state.py status` 输出的 `site.outdated` 为 true，说明官网用到的店铺资料改过了；`site.changed` 写着是哪几样，例如“门店”“这家店的特点”。

- 每周出周报时看到，就在建议里提一次：“官网上的门店信息过时了，要更新吗？”商家同意了再更新，没理会就不再提。
- 要更新，或者商家说“官网上……改一下”：重新执行 `site-brief` 拿最新的资料，交给“应用”能力改同一个应用，从第 4 步往下走。

## 商家说

| 商家说 | 做法 |
| --- | --- |
| “帮我做个官网” | 从第 1 步开始 |
| “官网可以发布了”“确认发布” | 按第 5 步；“应用”能力要求他确认的是这一轮看过的测试版，隔了几轮才说，按它的规矩先重出测试版 |
| “官网上……改一下”“更新官网” | 按“改官网、更新官网” |
| “官网发我” | `site-brief` 输出里的 `site.url`；还没上线，就说还在测试版，给 `site.testUrl` |
| “官网绑好域名了：……” | `set-site --domain <域名>` → `publish`。以后这个域名下的页面被 AI 引用，也算他自己的内容 |
| “官网不要了” | 按“应用”能力下线、删除的流程，商家明确确认后再做；做完 `set-site --status dropped` → `publish`。以后再要，就是从第 1 步重新做一个 |
