# 工作台

商家看这份工作只用打开一个地方：**工作台**，一个固定的链接，左边是导航，右边是内容。

- 工作台只放跨期的东西：最新一期的结论、几个数的走势、每一期报告的入口、你替他写的内容、监测设置。
- **体检报告**每期一份，是独立的文件。在工作台里点某一期，报告就在右边打开；报告文件也可以单独打开，商家要转发给别人时用。

页面都是只读的：商家在上面看，回到对话里跟你说；你改数据，再同步。页面是“模板 + 数据”每次同步重新生成的，**不要直接改生成出来的网页文件**，下次同步会被盖掉。

本 Skill 只管页面本身。页面上的东西从哪来：监测设置是 `geo-profile` 写的，体检结果是 `geo-check` 算的，小结和建议是 `geo-weekly` 写的，内容是 `geo-content` 登记的，官网是 `geo-site` 登记的。

脚本是 `python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py"`，下文的 `geo_report.py ...` 是它的简写，执行时写全。别的 Skill 的脚本同理：`geo_state.py` 在 `geo-profile` 下，`geo_run.py` 和 `geo_score.py` 在 `geo-check` 下。

## 同步：只有一条命令

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" publish
```

它重新生成这一期的报告和工作台、传到云盘、保存链接。输出里：

- `published: true`：同步成功。
  - `pageUrl`：工作台。
  - `reportUrl`：在工作台里打开这一期的报告。**说到这一期的结果时，发给商家的是它。**
  - `reportSections`：直接打开这一期报告某一节的地址（`summary` 结论、`mentions` 有没有提到你、`rivals` 提到了谁、`sources` 读哪里的内容、`says` 怎么介绍你）。说到某一节时给那一节的。
  - `links`：可以直接发给商家的几个链接（工作台、内容、监测设置、这一期的报告）。
  - `reportFileUrl`：报告文件自己的链接。只有商家要把报告单独转发给别人时才给。
  - `synced`：这次同步上去的变化。
- `firstTime: true`：第一次开通。接着按 `references/tabs.md` 把工作台固定到客户端页签，再把 `pageUrl` 发给商家，告诉他以后都在这里看。
- `unfinished`：最近一期体检还没做完（会话断过，或者还在做）。这时的报告不完整，或者还是上一期的，先别当成这一期的结果发给商家，照 `unfinished.next` 做完再同步。
- `published: false`：没全部传上去，按下面的“同步失败时”处理。

链接只用输出里的，逐字照抄，不改域名、不解码、不重新拼。页面上已经有的，对话里不重复贴。

拿不准页面是不是最新的：`geo_state.py status`、`geo_report.py links`、`geo_report.py show` 的输出里都有 `pending`，不为空就先 `publish` 再发链接。改了数据的命令，输出的 `next` 也会提醒。

## 什么时候同步

| 时机 | 为什么 |
| --- | --- |
| 建完档，体检之前 | 第一次开通工作台，接着固定客户端页签。商家可以先在上面看问题 |
| 发起体检之后 | 工作台显示“体检进行中”，商家打开不会看到旧内容却不知道在更新 |
| 核对和本期小结都写完之后 | 生成这一期的报告，工作台换成这一期的结论 |
| 登记或改了内容之后 | 稿子要在工作台上才看得到 |
| 商家让你改了任何东西之后 | 他会马上回去看 |

等待查询返回的过程中不用反复同步。

## 同步失败时

`publish` 输出 `published: false` 时，页面已经在本地生成（工作台是 `file`，报告是 `reportFiles`），只是没全部传上去，`reason` 里写着是哪个：

1. 先再执行一次 `publish`。
2. 还是不行，改为调用 `youzan-oss` Skill 给没传上去的文件生成云盘链接，再存回来：工作台用 `geo_report.py set-page-url --url "<返回的 url>"`，报告加上 `--report <日期>`。
3. 都不行：如实告诉商家页面暂时没更新，周报照发，不带链接。**不要编一个链接。**

报告文件没传上去时，`reportUrl` 是空的：工作台里打不开这一期。这时不要自己拼一个地址。

## 你做的事 → 落在哪

| 你做的事 | 命令 | 落在哪 |
| --- | --- | --- |
| 读店铺资料 | `geo_state.py set-facts` | 不展示。它是你核对和写内容的底稿 |
| 写差异点、出题、选同类店 | `set-facts`（`edges`）、`set-questions`、`set-rivals` | 工作台 · 监测设置 |
| 另外记下后台里没有的信息（别的叫法、已关的旧店；他说的公众号、抖音号） | `set-facts` | 工作台 · 监测设置（你推断的那几样等他确认） |
| 商家同意开启每周体检 | 建定时任务，`geo_state.py set-schedule --status on` | 不展示。每周一出新的一期报告 |
| 发起体检 | `geo_run.py start` | 工作台首页显示“体检进行中” |
| 算分 | `geo_score.py score` | 这一期的报告：有没有提到你、提到了谁、读哪里的内容；工作台首页的几个数 |
| 读全文：每个回答推荐了哪几家店、复核“提到你”和“和你有关的引用”、这一期的发现 | `geo_score.py set-reading`、`set-findings` | 这一期的报告 · 提到了谁、有没有提到你、读哪里的内容；这一期的报告 · 结论（“这一期的发现”，最多 5 条，每条带 AI 的原话） |
| 核对 AI 怎么介绍这家店 | `set-judgement` | 这一期的报告 · 怎么介绍你。有和店铺资料对不上的才列出来 |
| 写本期小结 | `set-actions` 的 `brief` | 工作台首页最上面；这一期的报告 · 结论 |
| 建议商家做的事 | `set-actions` 的 `todos` | 这一期的报告 · 结论（“这一期建议你做的”） |
| 找内容缺口 | `set-actions` 的 `gaps` | 这一期的报告 · 读哪里的内容（工作台上不放，它是那一期的分析） |
| 写内容（公众号文章、小红书笔记、长文、抖音视频文案） | `geo_report.py add-content`，要写明类型 | 工作台 · 内容；有等他确认的，首页会多出一块“等你确认的内容” |
| 内容确认了、放进草稿箱了、发出去了 | `geo_report.py mark-content --no N …` | 工作台 · 内容 |
| 官网出了测试版、正式上线、绑了域名、不要了 | `geo_report.py set-site`（按 `geo-site`） | 工作台 · 内容，最上面一块；AI 引用了已上线的官网，算进“你的内容被引用” |
| 填员工负责的页面（登记好的，或这家店单独加的） | `geo_report.py set-page --id <页面> --file …` | 工作台 · 那一页，排在三个固定页面之后 |

工作台首页只有这几样：最新一期的结论和你写的小结、四个数、等他确认的内容（有才出现）、每一期的报告。不要指望在首页上放别的东西；某一期的分析都在那一期的报告里。

## 内容在页面上怎么展示

内容按 `geo-content` 写和登记，工作台“内容”页按类型展示：公众号文章给“看排版预览”的入口；小红书笔记、抖音视频文案显示标题、正文和话题，可以一起复制；长文显示全文，可以复制。每条有固定的序号，显示成“第 4 篇”。

做了官网的，“内容”页最上面多一块官网：上线了给“打开官网”，有测试版等确认给“看测试版”，店铺资料改过会提示更新。

页面上的链接在客户端里这样打开：公众号文章的“看排版预览”在工作台里弹出来看；官网、报告里 AI 引用的原文这些别的网站，交给客户端用浏览器打开；打不开时页面会弹出链接，让商家复制到浏览器里。

## 页面清单

工作台固定有三个页面，由脚本按存档生成。另外还可以有员工负责的页面（见 `references/pages.md`），它们排在这三个页面之后，链接末尾是 `#/` 加页面的 id，`publish` 和 `links` 的输出里会给出来。

| 工作台的页面 | 链接末尾 | 商家在这里做什么 |
| --- | --- | --- |
| 工作台 | `#/overview` | 看最新一期的结论和小结、几个数和走势、等他确认的内容、每一期报告的入口 |
| 内容 | `#/content` | 确认、复制去发：你替他写的每一条内容，按类型展示；做了官网的，最上面是官网 |
| 监测设置 | `#/settings` | 看和改：这家店的特点、每周问 AI 的问题、和谁比，以及你另外记下的信息 |

在工作台里看某一期的报告，链接末尾是 `#/report/<日期>`，例如 `#/report/2026-10-08`。`reportUrl` 和 `links` 里“这一期的报告”就是这个地址，不用自己拼。

报告从上到下五节。每一节的地址在 `publish`、`links`、`show` 输出的 `reportSections` 里，照抄就行，也不用自己拼：

| 报告里的小节 | 小节 | 内容 |
| --- | --- | --- |
| 结论 | `summary` | 这一期的结论、小结、几个数、这一期的发现、建议做的事 |
| 有没有提到你 | `mentions` | 每道题每个平台有没有提到这家店；点一格看 AI 的原话和它引用的内容 |
| 提到了谁 | `rivals` | 顾客没点名时，AI 点名提到的所有店，各出现在几个回答里、分平台；选定的同类店在里面标出来 |
| 读哪里的内容 | `sources` | 各平台读哪里的内容，引用了哪些和这家店有关的内容，还缺什么 |
| 怎么介绍你 | `says` | 点名问时 AI 怎么介绍这家店；有和店铺资料对不上的说法才列出来 |

还没体检过的时候，工作台首页显示“现在到哪一步了”，没有报告，这是正常的。

## 商家说到页面和链接

| 商家说 | 做法 |
| --- | --- |
| “把报告发我”“第 2 期的报告发我” | `geo_report.py links`：最新一期给 `reportUrl`，以前的在 `reports` 里按日期找 |
| “把报告单独发我一份，我要转给合伙人” | `links` 里的 `reportFileUrl`（以前各期在 `reportFiles` 里）。这个链接打开只有报告，没有工作台的导航 |
| “把工作台发我”“我想看看整体情况” | `geo_report.py links`；`pending` 不为空先 `publish`。给“工作台”的链接 |
| “工作台上加一个页面，放……”“把活动安排放到工作台上” | 先看是不是已经有合适的页面（`geo_report.py pages`）。没有、而且放的是跨期的、商家会反复来看的东西，就按 `references/pages.md` 的“员工负责的页面”单独加一页 → `publish`，给 `links` 里这一页的链接。某一期的分析不要做成页面，它在那一期的报告里 |
| “页面换个颜色”“字大一点”“首页上加一块……”“把这块去掉”“改回原来的样子” | 按 `references/pages.md` 的“改这家店的页面”：改这家店的模板（还没有就先 `template-init`），改回原样用 `template-reset` → `publish`，给改了的那一页的链接 |
| “活动页上的……改一下”“那个页面不要了” | 改：`set-page` 传整页的新内容块 → `publish`；不要了：`geo_report.py remove-page --id <页面>` → `publish` |
| “工作台里的链接点不开”“预览打不开” | 先 `publish` 一次，让工作台用上最新的页面；还是打不开，页面会弹出链接让他复制到浏览器里打开。以前各期的报告不会重新生成，里面的链接在客户端里可能点不开，告诉他这是旧报告，需要时把那一期报告的单独链接（`links` 里的 `reportFiles`）发给他，在浏览器里看 |
| “新增嵌入 tab”“客户端嵌入工作台”“固定页签”“页签里看不到” | 按 `references/tabs.md`。这是客户端的页签，不是给工作台加页面 |

## 加页面、改样子、客户端页签

- 在工作台上多放一页清单、说明、表格，或者改颜色、布局、在已有页面上加模块：按 `references/pages.md`。
- 把工作台固定到客户端的页签：按 `references/tabs.md`。

改标准模板、给所有店加页面是维护的人的事，写在员工定义目录下的 `MAINTAINING.md` 里，员工不用读。
