# 每一期的收尾和周报

体检（`geo-check`）算出数、读完回答、核对完以后，这一期的数据就齐了，但还没有结论，报告也还没生成。本 Skill 把这一期收尾：对比、找缺口、写小结和建议、生成报告，再把结果告诉商家。

它负责整体流程（见角色设定的“工作方式”）里的第 4、5 步：第一份报告出来后汇报、问商家要不要开启每周体检；以后每周出周报。`geo_state.py status` 返回 `firstCheckPending` 为 true 时，还在等商家确认第一次体检，这时不收尾、不写内容。

## 开始前

- 同步页面、发哪个链接、同步失败怎么办，按 `geo-workbench`。写内容按 `geo-content`。

## 第一份报告（整体流程第 4 步）

商家确认后跑完第一次体检（`geo-check` 的算分和核对都做完），按下面“每周出周报”的第 1 到第 5 步做：对比（第一期没有可比的）、找内容缺口、写第一篇内容、写小结和建议、同步。然后给商家发一条消息，让他知道：顾客没点名时多少个回答提到了他、AI 点名介绍他时怎么说、这一期的报告（`publish` 输出的 `reportUrl`）、写了的第一篇内容（给“内容”页的链接；没写就说为什么），最后问他要不要开启每周体检（以后每周一上午自动问一遍、出报告、备好一篇内容）。报告里有的不要再贴一遍。商家回复后按下一节做。

## 开启每周体检

每周体检由你替商家开启，不是一上岗就有。**只在商家明确同意后开启**，只问一次；商家没回、说再看看，就不开，以后在周报里也不催。

商家同意后，用运行时提供的创建定时任务的能力，建一个这样的任务：

| 项 | 填什么 |
| --- | --- |
| 名称 | 每周 AI 曝光体检 |
| 时间 | 每周一 9:00，时区 Asia/Shanghai（cron：`0 9 * * 1`） |
| 每次触发时对你说的话 | 下面这一段，原样填 |

```text
每周 AI 曝光体检：先执行 geo-profile 的 status。firstCheckPending 为 true 时只提醒商家确认，不体检；schedule 不是 on 时说明商家已经关掉了每周体检，不体检，结束。最近一期没做完（period.done 为 false）：是今天的就照 period.next 接着做完；是以前的就不补了，照常开始新的一期。
否则按 geo-profile 重读店铺资料，再依次用 geo-check 和 geo-weekly 完成本周体检和周报，直接执行，不询问确认。
这一期写的内容先登记到工作台，等商家确认后再发；现在不能替商家写内容时不写，只请商家看一眼工作台的“监测设置”。
结束时用一句话总结：“本周体检完成：Y 个回答里有 X 个提到本店，本周内容：待确认 / 未写。”
```

建好以后读回确认任务存在、时间对，再记下来，并告诉商家每周一上午会收到周报：

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-profile/scripts/geo_state.py" set-schedule --status on
```

其他情况：

| 情况 | 做法 |
| --- | --- |
| 商家说先不开 | `set-schedule --status declined`。告诉他想做的时候说一声“开启每周体检”，或者随时说“重新体检” |
| 商家后来说“开启每周体检” | 照上面建任务，`set-schedule --status on` |
| 商家说“每周体检停掉” | 用运行时的能力停掉或删掉这个任务，`set-schedule --status off` |
| 当前环境没有创建定时任务的能力，或者建了读不回来 | `set-schedule --status unavailable`。如实告诉商家暂时开不了自动体检，他想看新结果时说“重新体检” |

## 每周出周报（整体流程第 5 步）

前提：当期已经按 `geo-check` Skill 完成体检（算分和核对都做完）。没做完时先去做。

### 1. 和上一期对比

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" compare
```

`notes` 里的话要照办：第一期没有可比的上一期；没有连续两期同方向变化时，只能写“继续观察”，不能写“上升”或“下降”；数据不全时不和上一期比。

### 2. 找内容缺口

看 `geo-check` 算分输出的 `sourcesByProvider`（每个 AI 各自最常读哪里、各占多少）和 `refs`（其中有多少是这家店的）；不在同一轮对话里时用 `geo_report.py show`，里面是同一份数。某个 AI 常读、而这家店在那里没有内容的地方，就是缺口。最多写 3 条。

**往哪发、补什么，依据只用这里的数**，规则：

- 每条缺口和每条“往哪发”的建议，都写明是哪个 AI、读哪里、占多少，数字照抄脚本输出。例如“豆包 45% 的引用来自抖音，这家店的抖音内容一次都没被引用”。
- 按占比排先后：哪个 AI 读得最多的地方排最前。不在任何一个 AI 前四名里的地方，不作为优先建议。
- 要补门店页、地图、工商信息这类资料时，写出数据里实际出现的网站名（“天眼查”“电话邦”“苹果地图”），不要换成数据里没有的平台。
- 子 Agent 读全文时说的“AI 常读哪里”只作参考；和脚本的数对不上时，以脚本为准。

### 3. 这一期的内容

按 `geo-content` Skill 定类型、选题、写稿、登记，用的就是上一步找到的缺口。资料还不能用来写（`canWrite` 为 false）或者没有合适的选题时，这一期不写，原因在下一步写进 `contentNote`。

### 4. 写本期小结、建议，保存

这一步写的东西商家会逐字看到：

- `brief`：本期小结，显示在工作台最上面和这一期报告的开头。两三句话、240 字以内：这一期最重要的一件事，和要商家做什么。只说存档里有的事实，数字和脚本输出一致；`compare` 的 `trend` 不是 `up` 或 `down` 时不写“上升”“下降”。这一期有发现（`geo-check` 第三步写的）时，最重要的一件事通常就是其中一条，小结里说一句，细节留在报告里。
- `todos`：建议商家做的事，最多三件，列在这一期报告的结论里。它只是建议，不是要打勾的清单。十分钟内能做完的排前面，每件写清做什么、为什么；核对出来的问题，只挑改得动、值得改的那一条。先看第 1 步输出里的 `previousTodos`（上一期建议过什么）：商家做了的不再提，没理会的最多再提一次。
- `gaps`：第 2 步找到的缺口，最多三条。`where` 写平台（公众号、抖音、地图和点评……），`note` 写缺什么、依据是什么。
- `contentNote`：这一期没有写内容时，写一句原因。写了就留空。

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" set-actions --file "$YOUZAN_AGENT_SESSION_TEMP/geo/actions.json"
```

```json
{
  "brief": "",
  "todos": [{"text": "", "why": ""}],
  "gaps": [{"where": "公众号", "note": ""}],
  "contentNote": ""
}
```

以后只改其中一样时，只传那一样，其余保持不变。写完小结以后又重新算了分、数变了（改了题、换了同类店），`status` 和 `publish` 会提醒你重写小结和建议。真正要商家点头的只有两件事，页面上都有固定的入口，不用靠建议去催：确认一篇内容（工作台 · 内容）、确认你另外记下的信息（工作台 · 监测设置）。

也看一眼 `show` 输出里的 `site`：做了官网、`site.outdated` 为 true 时，官网上的信息已经跟不上店铺资料了（`site.changed` 写着哪几样变了）。在 `todos` 里提一次要不要更新，商家同意了按 `geo-site` 更新；提过一次没理会，就不再提。

### 5. 生成这一期的报告

```bash
python3 "$YOUZAN_AGENT_SESSION_WORKSPACE/.claude/skills/geo-workbench/scripts/geo_report.py" publish
```

这一步生成这一期的报告，并把工作台换成这一期的结论。输出怎么看、同步失败怎么办，按 `geo-workbench`。

输出里有 `warnings` 时照着处理。最常见的两条：“这一期既没有登记内容，也没有写没写的原因”：内容写了就补登记，没写就补原因；“已经登记了内容，但 contentNote 里还写着没写的原因”：用 `set-actions` 传 `{"contentNote": ""}` 清掉，并看看小结要不要跟着改。

### 6. 给商家发周报

让商家知道：顾客没点名时多少个回答提到了他（和上一期怎么比，按第 1 步的 `notes` 说）、这一期最值得他知道的一件事、这一期的报告（`reportUrl`）、要他做的一件事（有内容等他确认给“内容”页的链接，有信息等他确认给“监测设置”的链接，都没有就说建议里的第一件）。明细都在报告里，不要贴在对话里。

每周定时任务触发的这一轮结束时，再按任务里的要求输出那一句总结。

## 商家问这一期、这几期怎么样

问题（Q3）、同类店、账号按 `geo-profile`；体检和“3 号”按 `geo-check`；“第 4 篇”、写内容按 `geo-content`；要链接按 `geo-workbench`；官网按 `geo-site`。下面是本 Skill 接的：

| 商家说 | 做法 |
| --- | --- |
| “开启每周体检”“每周体检停掉” | 按上面的“开启每周体检” |
| “你建议的那件事我做了”“这件我做不了” | 回一句就行，不用登记。做不了的，下一期不要再提；他处理的如果是报告里的某一号，按 `geo-check` 记一笔 |
| “AI 提到了谁”“豆包推荐了哪些店” | 只用这一期报告“提到了谁”那一节的排行回答，说前几家和次数，给那一节的链接（`reportSections` 里的 `rivals`，照抄）。不要自己翻回答原文另列一份：口径不一样，商家拿报告一对就对不上 |
| “你建议我写什么”“往哪发”“AI 都读哪里” | `geo_report.py show`：`sourcesByProvider` 是各平台读哪里（和报告上的数一样），`gaps` 是本期写下的缺口，`refs` 是和这家店有关的内容被引用几次。按平台说，不要自己翻回答原文重新归类。给报告“读哪里的内容”一节的链接（`show` 输出 `reportSections` 里的 `sources`，照抄） |
| “为什么元宝不提我”“怎么让 AI 多提我” | 用这一期报告里的内容回答：这道题 AI 引用的是谁的内容，这家店在那些地方有没有内容。给 `reportUrl` |
| “这周怎么样” | `compare` 的结果，加 `reportUrl`。不重新体检 |
| “你都做了哪些事”“之前几期怎么样” | `geo_report.py show` 的 `totals`（体检了几期、写了几篇、发了几篇），两三句话概括，给工作台首页的链接 |
