# 内容：按类型写，按类型登记

替商家写的东西统称“内容”。不同平台的稿子不是同一份文字换个排版：公众号文章是带排版的长文，小红书笔记是短标题、短正文加话题，知乎回答是对着一个问题写的长文。所以每一条内容都有一个**类型**，稿子长什么样、谁来写、商家在哪审、确认后怎么交，都跟着类型走。

| 类型 | `type` | 稿子 | 谁写 | 商家在哪审 | 确认后 |
| --- | --- | --- | --- | --- | --- |
| 公众号文章 | `wechat` | 带排版的长文（HTML） | 公众号技能 | 工作台上点“看排版预览” | 存进公众号草稿箱 |
| 小红书笔记 | `xhs` | 标题 20 字以内，正文 1000 字以内，加话题 | 你自己 | 工作台上直接看 | 商家复制去发 |
| 长文 | `text` | 纯文字长文（知乎、头条号、百家号、搜狐号） | 你自己 | 工作台上直接看 | 商家复制去发 |

工作台只认公共的那一层（序号、类型、标题、状态、放到了哪）。稿子是谁写的、用哪个技能写的，它不关心，只记这种类型交回来的东西。

## 红线（所有类型都一样）

1. 只写店铺资料里有的事实，和店铺数据里查得到的内容。数字必须有出处。你另外记下、商家还没确认的信息（他的账号、别的叫法、已经关掉的旧店）不写进稿子。资料不是从店铺后台读的、商家也还没看过时，这一期不写，脚本也会拒绝登记。
2. 不编造测评、榜单、排名、奖项和顾客评价；不用“第一”“最好”“唯一”这类绝对化用语；不贬低其他商家。
3. 每期主动写的最多 2 篇，不写内容相近的批量稿。脚本会卡住第 3 篇。
4. 只为商家自己的官方账号准备内容。不代注册、不代管账号，不向第三方媒体投稿。
5. 存入草稿箱和发布之前，必须得到商家对这一篇的明确确认，并提醒按平台要求标注 AI 生成。
6. 图片地址、小程序路径、链接只能来自查询结果或商家提供的内容，禁止凭记忆填写。
7. 遵守商家提过的写作要求（店铺资料里的 `writingRules`）：口吻、不用的词、每篇必须带的信息。

## 先定写哪种类型

看三样东西：这一期各平台最常读哪里（`geo_report.py show` 的 `sources`，和报告上的是同一份数，按平台看）、这家店在哪里没有内容（内容缺口）、商家有哪些账号（店铺资料的 `channels`，要是他确认过的）。

| 情况 | 写什么 |
| --- | --- |
| 元宝常读公众号，商家有公众号并且已经授权 | 公众号文章 |
| DeepSeek 常读知乎，文心常读搜狐号和百家号，元宝也读头条 | 长文，`whereToPost` 写清建议发在哪 |
| 商家没有公众号 | 长文 |
| 商家点名要某一种（“写一条小红书笔记”） | 按他说的类型写，`origin` 写 `asked` |

- 表里的平台只是常见情况，以这一期 `sources` 里的数为准；说给商家听时用报告上的数，不要用这里的。
- 两次实测里，这几个 AI 都没有引用过小红书的内容。所以不要主动写小红书笔记，商家点名要时再写。这一期 `sources` 里有小红书时，以这一期为准。
- 同一个主题要发两个平台，就按两种类型各写一条、各自登记。**不要把一种类型的稿子原样搬到另一个平台。**
- 商家没有对应的账号时不替他注册，改写他有账号的类型。

## 选题顺序

1. **正面回答一道没提到本店的问题**（默认）。从这一期没提到本店的问题里挑一道，挑的时候看三点：这家店有真实内容可写；AI 回答这道题时引用的内容里，你打算写的那种类型占比不低；最近四期没有为同一道题写过。
2. **写一篇带日期的信息说明**（少数情况）。这一期报告里有会让顾客跑错地方或买错东西的说法，而且出处是别人写的内容、原文改不了时，可以把这一期的内容换成它。本地门店写门店信息（现在有哪几家店、地址、营业时间、哪些店已经搬走或关闭）；电商写商品和购买信息（规格、价格带、在哪买）。同一件事只写一次，不要每期都写。
3. 两者都没有合适的：这一期不写，用 `set-actions` 把原因写进 `contentNote`。不为了凑数硬写。

`forQuestion` 填这篇对应的问题编号；信息说明类的留空。

## 公众号文章（`wechat`）

**稿子**：AI 引用内容时，偏好能直接回答问题、事实清楚、有日期的文章。

- 标题用顾客的问法，或者直接写清主题，64 个字以内。不用夸张的标题。
- 开头两句直接给答案：这家店是什么、在哪、适合谁。
- 正文三到五个小标题，每段先说结论，再给事实。600 到 1200 字。
- 事实写全：店名、地址（到门牌号）、营业时间、价格或价位、怎么买（小程序名称或店铺入口）。
- 文中写明“信息更新于某年某月”。结尾一句话写清怎么找到这家店。

**谁写**：公众号要的是带排版的 HTML，由公众号技能产出，你不要自己拼 HTML。用 Agent 工具委派给 `wechat-writer` 子 Agent（`subagent_type=wechat-writer`），交代清楚：

- 选题和对应的问题原文。
- 店铺资料全文（先去掉商家还没确认的那几样），并说明“只能使用这里面的事实”；商家提过的写作要求；上面的红线和写法。
- **只生成排版预览，不要存入草稿箱。**
- 正文和预览文件用带序号的文件名。序号用 `contents` 输出的 `nextNo`，例如第 4 篇用 `output/geo-4-article.html` 和 `output/geo-4-preview.html`。它默认每次都写同一个文件，不交代的话，新的预览会把上一篇的盖掉。

**它交回来的**：排版预览链接。

**登记**：`type`、`title`、`previewUrl`（逐字照抄它给的链接）。手里有文字版可以放进 `body`，没有就不放。

**确认后**：再次委派 `wechat-writer` 把这一篇存入草稿箱，然后记一笔：

```bash
python3 "$REPORT" mark-content --no 4 --channel 公众号草稿箱 --ref <它返回的草稿编号>
```

`ref` 以后改稿时原样交还给它，让它在原草稿上更新。没有公众号、或者存草稿失败时，如实告诉商家，状态保持“已确认”。

**改稿**：让 `wechat-writer` 改，拿到新的预览链接后 `add-content` 带上 `no`。

## 小红书笔记（`xhs`）

**稿子**：和公众号文章是两份东西，不要拿文章删减。

- 标题 20 个字以内，说清是什么、给谁看。
- 正文 1000 字以内，一般 200 到 500 字。第一人称，口语，分点写，可以用表情符号。
- 写清地址、营业时间、怎么买。
- 结尾 3 到 8 个话题，放在 `tags` 里，不要写进正文。
- 配什么图写在 `tip` 里，一句话。

**谁写**：你自己写。

**登记**：`type`、`title`、`body`、`tags`、`tip`。标题超过 20 个字、正文超过 1000 字，脚本会退回来，不会替你截断。

**确认后**：商家在工作台上点“复制标题、正文和话题”，自己去发。不代发。

## 长文（`text`）

用于知乎回答、头条号、百家号、搜狐号这类纯文字的长文。

**稿子**：写法和公众号文章一样（见上面的“稿子”），但是纯文字。可以用 `#` 开头的小标题和 `**加粗**`，不要放 HTML。写知乎回答时，标题就用那个问题的原话。

**谁写**：你自己写。长稿先存成文件，登记时用 `bodyFile` 给出路径，不用在 JSON 里转义。

**登记**：`type`、`title`、`body` 或 `bodyFile`、`whereToPost`（建议发在哪）。

**确认后**：商家在工作台上点“复制全文”，自己去发。

## 两种长文的骨架

门店信息说明：

1. 一句话说明这是谁、这篇是什么（“这是某某的官方门店信息，更新于某年某月”）。
2. 现在营业的门店：每家一段，写名称、地址、营业时间、电话。
3. 已经搬走或关闭的门店：写清旧地址和现在的情况。只写店铺资料里有、并且商家确认过的。
4. 怎么线上下单：小程序名称。
5. 一句提醒：其他地方看到的地址和营业时间与本文不一致时，以本文为准。

选购问答（电商）：

1. 用顾客的原话写出问题，接着两句话给出答案。
2. 这类需求怎么选：两到三条判断标准，每条配这家店对应的商品和规格。
3. 价位和规格：只写店铺资料里的价格带。
4. 在哪买：小程序名称、怎么搜到店铺。
5. 常见的两三个追问，各用一两句话回答。

## 写完怎么交（所有类型）

不管是每周主动写的，还是商家临时要的，写完都按这四步走：

1. **登记**。登记了，工作台“内容”页才有它；不登记，它就只存在于对话里。

   ```bash
   python3 "$REPORT" add-content --file "$YOUZAN_AGENT_SESSION_TEMP/geo/content.json"
   ```

   ```json
   {"type": "text", "title": "", "bodyFile": "", "reason": "", "forQuestion": "q07", "whereToPost": "知乎", "origin": "weekly"}
   ```

2. **同步工作台**：`python3 "$REPORT" publish`。
3. **告诉商家**：类型、标题、两三句摘要，和工作台“内容”页的链接。**不要在对话里贴全文**，稿子在工作台上。商家明确要在对话里看时可以贴，贴的必须是登记的那一版。
4. **等他确认**。他说“第 4 篇可以发”，再按这种类型的“确认后”去做。

改稿：改好后 `add-content` 带上 `"no": 4`，只传改了的部分。商家确认过的稿子改了以后会变回“等你确认”。

## 加一种新类型

`geo_report.py` 的 `CONTENT_TYPES` 里加一行规格（标题上限、正文上下限、要不要话题、成品是不是带排版的页面），本文件加一节写法。工作台和其他命令不用改。
