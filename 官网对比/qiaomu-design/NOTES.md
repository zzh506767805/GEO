## Skill 要求的关键步骤
1. 设计读取：一句话定性 + 三拨盘（视觉冒险度 / 动效强度 / 信息密度）+ 功能契约。
2. Phase 2「风格试衣间」：四个轴级差异的方向（A/B/C/D），做成真实 mini mockup 预览页，标推荐，等用户选择后才实现。
3. Phase 3：编译 build brief → 写项目级 DESIGN.md → 从 58 站库挑 1–2 个供体，偷 3–5 个具体值 → 实现 → 截图后从艺术总监 / 工程师 / 甲方 / 读者四个角度挑问题，第二轮只修这几处 → 最后一轮做减法 → 过 preflight。
4. 硬边界：禁紫蓝光晕、渐变字、居中 Hero + 三卡片、卡片海、左侧竖线、斜体、`transition: all`；中文正文用系统字体栈；CTA 全页同一说法；必须有 reduced-motion。

## 设计决定
- 配色：Intercom 的暖白画布 #faf9f6 + 燕麦边框 #dedbd6；品牌蓝 #155bd4 是唯一重音，只用在 CTA、提问气泡和关键词上；绿色只用来标“已连接店铺后台”。
- 字体：中文全用系统栈，字重 400 / 500 / 600，没有负字距；JetBrains Mono 只用在西文小标签和“16”这个大数字上。没用装饰中文字体。
- 形状和深度：按钮和 chip 4px，面板 8px（Intercom）。抬起的元素用 Stripe 的双层染色阴影，改染成品牌蓝。
- 版式：分屏 Hero，左边文字，右边是三层对话台示意（底纸 → 对话窗 → 浮动的“数据来源”和“示意”标签）。“它认识你的店”一节用三个大字词（卖什么 / 开在哪 / 顾客是谁）。四块能力用 2×2 细线网格，不做成卡片。工作台一节是连接示意 + 大号“16”。多渠道一节画汇流线，数字员工一节画四步时间线。FAQ 用原生 details。
- 签名交互：页面上所有“随口一问”都能点，点了以后对话台先出打字点，再出回答示意。回答里只有骨架条，没有数字，并标注“界面示意”。
- 动效：入场只位移 10px 加淡入，320ms，ease-out；按钮按下 scale(.97)；状态点有呼吸效果；hover 只在指针设备上生效；开了 reduced-motion 就去掉位移和循环动画。
- 两轮修正：第一轮截图后改了这些——H1 原来断成四行，改为两行；“顾客是谁”和几个 H2 有孤字换行；手机上 2×2 网格多出一条竖线；手机上连接线被拉伸变形。减法一轮删掉了重复的“对话框”小标签、技能列表的 01–05 编号，以及单独一行的接入日期（并进了正文）。

## 长处
- 先出四个方向、再选一个，能防止一上来就做成同一种 AI 模板。推荐的方向要说出理由。
- 功能契约、中文排版纪律、可读性红线、CTA 统一、preflight 这些规则很具体，可以逐条核对。
- 58 站 DESIGN.md 能提供实际数值（阴影、圆角、色值），不用凭感觉。

## 局限
- 流程很重，而且依赖有人在旁边：Phase 2 必须等人点选，还要起回传服务。在自动化或批量场景里只能变通。
- 规则很多（偏好账本有 40 多条，有些是阅读器、封面这类不相关的场景），读起来上下文成本高。
- 它的“高保真 Hero 组件要有真实数据”和本次“不编造数字”的要求冲突，只能用骨架条代替数据。
- 供体都是英文站点，中文营销页的气质主要还得靠自己判断。
